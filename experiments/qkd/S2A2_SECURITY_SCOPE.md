# S2.A2 experimental authenticated syndrome reconciliation

- This additive module is a bounded-distance reference decoder, **not** a production LDPC decoder, full QKD error-correction proof, or a qualified secret-key source.
- A public per-block 32-by-up-to-128 parity-check matrix is generated independently of raw-key bits using a fresh 128-bit OS-random seed. Each column has ten nonzero entries. Construction validates that error patterns of Hamming weight 0, 1 and 2 have distinct syndromes before using the matrix.
- Bob independently decodes the authenticated syndrome difference and corrects at most two bit errors per 128-bit block; beyond that radius decoding can fail or miscorrect. A subsequent S2.A1 independent fresh-seeded Toeplitz confirmation aborts undetected discrepancies except with conditional bound 2^-t for fixed inputs independent of the confirmation seed. No local raw-key equality oracle is used for protocol acceptance.
- Each block publicly reveals **32 syndrome bits** (including for shortened final blocks); the 128-bit matrix seed is public, independent of the key and not counted as key leakage. This is a conservative per-block disclosure bound: rank reduction could improve accounting, but is not claimed. The S2.A1 confirmation tag discloses t additional bits; report uses sum of all blocks and the tag. HMAC authentication tags are not counted as raw-key leakage under independent provisioning assumptions, which are **not validated**.
- Public frame includes session ID, sequence number, block offset, matrix seed, width and syndrome. HMAC is an experimental channel; independently provisioned authentication and composable treatment of the MAC are outstanding.
- The module returns Bob's corrected bits to the **local test caller**, and a metadata-only report. It does **not** run privacy amplification, derive an HPKE PSK, qualify QKD, or authorize key export.
- S2.A3 must integrate a reviewed reconciliation mechanism with M2.A and the finite-key evaluator. S2.A2 explicitly leaves M2.A unchanged. This prototype may reject many high-QBER blocks; a production-grade LDPC/Cascade implementation with a documented decoder and leakage/performance analysis remains future work.
