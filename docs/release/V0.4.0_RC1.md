# PQC-rs v0.4.0-rc.1

`v0.4.0-rc.1` is the first public release candidate of PQC-rs, a
standards-driven Rust workspace for post-quantum cryptography and
post-quantum key establishment.

> **Licensing note:** The immutable `v0.4.0-rc.1` release candidate was
> published under `Apache-2.0 OR MIT`. The current `pqc-rs` development
> line and subsequent releases use the MIT License only. This document
> preserves the historical licensing terms of the release-candidate
> artifact.
>
## Published crates

- `pqc-rs-core` provides common traits, typed byte containers, errors, and
  explicit secret containers.
- `pqc-rs-ml-kem` provides ML-KEM-512, ML-KEM-768, and ML-KEM-1024 key
  generation, encapsulation, decapsulation, and key checks.
- `pqc-rs-hpke` provides HPKE Base and PSK modes with ML-KEM and
  revision-pinned pure post-quantum and post-quantum/traditional hybrid
  profiles.

All three crates require Rust 1.80 or later and are available under
`Apache-2.0 OR MIT`.

## Validation and engineering evidence

The release gate includes formatting, warning-free Clippy, workspace tests,
rustdoc, benchmark compilation, standards traceability, API and architecture
review, ACVP-oriented validation, interoperability checks, fuzzing,
interpreter and sanitizer checks, secret-lifetime review, and timing and
generated-code analysis.

The published packages were rebuilt from their crates.io dependency graph.
In particular, `pqc-rs-hpke` was verified against the published
`pqc-rs-core` and `pqc-rs-ml-kem` release candidates rather than workspace
path dependencies.

## Release boundaries

This is a pre-release and has not received an independent security audit or
formal certification. It is intended for research, evaluation, integration
testing, and external review. It should not be relied upon to protect
production secrets without independent review and an application-specific
risk assessment.

ML-DSA, SLH-DSA, the experimental `pqc-rs-hybrid` placeholder, and the
internal test harness are not published in this release. RFC 9958 is treated
as informational engineering guidance; normative claims are traced to the
applicable FIPS and RFC specifications. The post-quantum HPKE profiles remain
pinned to an Internet-Draft revision.

Stage 10B-5 cross-architecture generated-code and timing comparison remains
deferred until Linux ARM64 and x86-64 validation targets are available.

## Installation

```toml
[dependencies]
pqc-rs-core = "0.4.0-rc.1"
pqc-rs-ml-kem = "0.4.0-rc.1"
pqc-rs-hpke = "0.4.0-rc.1"
```

Applications should depend only on the packages they use. HPKE consumers do
not need to list its transitive PQC-rs dependencies explicitly.
